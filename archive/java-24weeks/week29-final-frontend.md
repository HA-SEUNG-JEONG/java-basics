**예상 시간:** 14~18시간 | **목표:** 24주차의 도서관 REST API 를 호출하는 **Next.js 클라이언트**를 처음부터 직접 만든다. 24주차의 시나리오 13개를 화면에서 재현하고, 400·401·404·409 가 서로 다르게 보이게 한다. 이 주차에는 빈칸도 채점기도 없습니다. **명세와 시나리오만 주어지고, 구현은 직접** 합니다. **마일스톤 점검 주차**입니다.

## 명세

### 화면

| 화면 | 경로 | 기능 | 호출 API |
|---|---|---|---|
| 책 | `/` | 책 목록, 제목 검색(`keyword`), 책 등록 폼 | `GET /books`, `POST /books` |
| 회원 | `/members` | 회원 등록 폼. 등록 결과로 **회원 id 를 보여 줌** (대출 화면에서 씀) | `POST /members` |
| 대출·반납 | `/loans` | 대출 폼(회원 id, 책 id), 내 대출 목록(회원 id 입력 → 반납하지 않은 대출, **반납 버튼**) | `POST /loans`, `GET /members/{id}/loans`, `POST /loans/{id}/return` |
| 공통 머리글 | 모든 경로 | 로그인 폼 / 현재 사용자 + 로그아웃, 화면 이동 메뉴 | `POST /auth/login`, `GET /auth/me`, `POST /auth/logout` |

### 인증

- **읽기(책 목록·검색, 대출 목록)는 로그인 없이**, **쓰기(책·회원 등록, 대출, 반납)는 로그인 후**에 됩니다. 로그인은 세션 쿠키(`JSESSIONID`)입니다. 데모 사용자는 `demo` / `demo1234`.
- 로그인 전에는 쓰기 버튼이 **눌리기 전에** 막혀 있고 이유를 보여 줍니다. 서버는 어차피 401 이지만 사용자가 눌러 보고 알게 하지 않습니다.
- "로그인 안 함"은 오류가 아니라 **정상 상태**입니다. 처음 열었을 때 `GET /auth/me` 가 401 이어도 오류 화면이 나오면 안 됩니다.
- 쓰기 중에 401 을 받으면(세션 만료 등) 화면의 로그인 표시도 즉시 로그아웃 상태가 됩니다.
- 토큰이나 세션 값을 `localStorage` 등에 직접 저장하지 않습니다. 쿠키는 브라우저가 알아서 싣습니다.

### 오류 표시

| 상태 | 의미 | 표시 |
|---|---|---|
| 400 | 입력이 잘못됨 | **해당 입력칸 옆**에 메시지. 폼 위 알림은 띄우지 않음 |
| 401 | 로그인 필요 | 로그인 안내 알림 |
| 404 | 대상이 없음 | "찾을 수 없음" 알림 |
| 409 | 규칙 충돌 (중복 isbn, 이미 대출 중, 3권 한도, 이미 반납) | "충돌" 알림. 입력칸 오류가 아님 |
| 그 외·네트워크 | 서버 꺼짐 등 | "요청에 실패했습니다" 류의 일반 알림 |

- 서버의 오류 본문은 항상 `{"message": "..."}` 입니다. 그 외 형식(프록시의 500 텍스트 등)도 깨지지 않고 일반 알림이 되어야 합니다.
- 400 의 `message` 는 `필드: 메시지, 필드: 메시지` 형태입니다. **문구에는 의존하지 말고 형식만 가정하세요.** 검증 메시지의 언어는 `Accept-Language` 에 따라 달라집니다(28주차).
- 알림의 문구가 같아도, 종류(색·제목·`data-` 속성 등)는 구분되어야 테스트할 수 있습니다.

### 품질 기준 (마일스톤 통과 조건)

- [ ] **생성 타입만 사용한다.** API 요청·응답 타입을 손으로 정의하지 않고 `openapi.json` 에서 생성한 파일만 쓴다. 호출에 원시 `fetch(` 도 없다. 스펙을 바꾸면 `pnpm typecheck` 가 호출부 오류를 낸다 (4단계)
- [ ] 400/404/409 (그리고 401)가 **서로 다르게 보인다.** 위 오류 표시 표를 지키고, 1단계 시나리오 13개가 모두 기대한 표시대로 동작한다
- [ ] **로그인 후 쿠키로 보호 API 를 호출한다.** 로그인 전 쓰기는 막히고, 로그인 후 등록·대출·반납이 되고, 로그아웃하면 다시 막힌다. 브라우저에서 `document.cookie` 에 `JSESSIONID` 가 보이지 않는다
- [ ] **MSW 로 백엔드 없이 화면을 개발할 수 있다.** 백엔드를 끈 채 `NEXT_PUBLIC_API_MOCKING=enabled pnpm dev` 로 책 목록·등록·로그인·대출·반납이 동작한다. 목은 `week25` 와 같은 상태 코드를 낸다
- [ ] **Vitest 8개 이상**이 백엔드 없이 통과한다 (MSW node 서버 사용). 구성 제안: 상태 코드 → 표시 종류 변환 3개 이상, 400 메시지의 필드별 분리 2개 이상, 클라이언트가 4xx 를 오류 객체로 바꾸는지 3개 이상
- [ ] **e2e 1개 이상**이 실서버(백엔드를 켠 상태)에서 통과한다. 최소 흐름: 로그인 전 쓰기 버튼 막힘 → 로그인 → 등록 → 같은 isbn 은 409 → 빈 isbn 은 400 (409 와 다른 표시)
- [ ] README 에 실행 방법(백엔드 → 프론트 순서), 환경 변수 표, 스크립트 표, **내가 내린 설계 결정 3개와 그 이유**를 적었다

## 힌트

정답 코드는 싣지 않습니다. 설계 판단의 단서만 줍니다.

- **상태 코드 변환은 한 곳에.** 화면마다 `if (status === 409)` 가 흩어지면 규약이 깨집니다. 변환 함수 하나와 오류 표시 컴포넌트 하나로 모으세요. (22주차의 `@RestControllerAdvice` 와 같은 구조)
- **400 과 나머지를 가르는 일.** 폼은 "입력칸 옆에 보일 오류"와 "폼 위에 보일 알림"을 따로 계산합니다. 같은 오류 객체에서 한쪽만 채워지면 둘이 겹쳐 보이지 않습니다.
- **브라우저 기본 검증을 끄세요.** 폼에 `noValidate` 를 주지 않으면 빈 칸이 서버에 닿기 전에 브라우저가 막아서 400 화면을 볼 수 없습니다.
- **로그인 상태는 한 곳에서 읽고 여럿이 봅니다.** 쓰기 버튼마다 따로 조회하면 요청이 늘고 값이 어긋납니다. 데이터 패칭 라이브러리의 캐시를 "로그인 상태 저장소"로 쓰면 로그인·로그아웃·401 에서 한 번에 갱신됩니다.
- **MSW 핸들러 경로**는 브라우저(`/api/...`)와 테스트(`http://localhost:8080/...`)를 둘 다 맞추게 쓰세요.
- **테스트 격리.** 목 DB 를 테스트마다 초기값으로 되돌리지 않으면 순서에 따라 결과가 달라집니다. 24주차의 "테스트는 실행 순서에 의존하면 안 됩니다" 가 여기서도 같습니다.
- **Node 의 `fetch` 는 쿠키를 저장하지 않습니다.** 로그인 상태를 MSW 가 흉내 내는 방식(변수 하나)은 쿠키가 아니라는 한계가 있고, 이 한계는 README 에 적을 만합니다.
- **e2e 의 데이터.** 백엔드 DB 가 실행 중 계속 남으므로 isbn 에 시간값을 섞으면 반복 실행해도 충돌하지 않습니다. 선택자는 CSS 클래스 대신 역할·레이블로 잡으세요.
- **설계 결정 후보 (README 3개).** 프록시 vs 직접 호출 / 데이터 패칭을 서버에서 할지 클라이언트에서 할지 / 오류 표시를 종류로 나눈 방식 / 로그인 상태를 둔 위치 / 목과 실서버의 어긋남을 관리하는 방법. 각각 "무엇을 선택했고, 무엇을 포기했는가"를 쓰세요.

## 확장 과제 (필수 아님, 마일스톤 후)

1. **계약 테스트:** 28주차의 방식으로 같은 시나리오를 목과 실서버에 모두 보내 어긋남을 CI 에서 잡기
2. **Route Handler(BFF) 비교:** 프록시 대신 `app/api/**/route.ts` 로 호출을 중계해 보고, 27주차 표의 항목별로 무엇이 달라졌는지 정리하기
3. **CSRF 토큰:** 백엔드와 합의해 CSRF 를 켜고 쓰기 요청에 `X-XSRF-TOKEN` 헤더 싣기 (CORS 허용 헤더도 함께)
4. **접근성 점검:** 키보드만으로 로그인·등록·대출·반납이 되는지, 오류 알림이 스크린 리더에 읽히는지
5. **낙관적 업데이트:** 반납 버튼을 누르면 서버 응답 전에 목록에서 지우고, 실패(11번 같은 409)하면 되돌리기
