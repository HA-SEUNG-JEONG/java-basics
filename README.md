# 프론트엔드 개발자를 위한 백엔드 협업 커리큘럼 (14주)

React·TypeScript·Next.js 로 일하는 프론트엔드 개발자가 **백엔드 개발자와 같은 말로 협업하고, 백엔드를 로컬에서 함께 띄워 디버깅**할 수 있게 되는 14주 로드맵입니다.

목표는 Java 를 능숙하게 쓰는 것이 아닙니다. 백엔드 팀이 보내 준 PR 에서 Java·Spring 코드를 **읽고**, API 계약(요청·응답·상태 코드·오류 본문)을 정확히 맞추고, Spring(8080)과 Next(3000)를 같이 띄워 문제가 어느 층에 있는지 좁히는 것입니다. 실습 대상은 저장소에 들어 있는 참조 API(도서관 API)이고, 이 API 는 "백엔드 팀이 준 API" 로 취급합니다. 직접 만들었다고 가정하지 않습니다.

## 전제

- **Node.js 22.12 이상**과 **pnpm 10 이상**이 필요합니다. 프론트엔드 실습(`labs/frontend`)에 쓰입니다.
- **JDK 21** 은 참조 API 를 실행하기 위해서만 필요합니다. Java 를 작성하는 실습은 없습니다.
- React·TypeScript 에 익숙하다고 가정합니다. 백엔드 용어는 TypeScript·프론트 용어와 나란히 놓고 설명하므로 Java 경험은 필요 없습니다.
- 학습은 **하루 1시간 세션** 단위로 계획합니다. 한 세션은 50~70분입니다. 각 주차 문서는 6~14개 세션(14주 최종 프로젝트는 16개)으로 나뉘고 전체는 118세션입니다. 각 문서의 예상 시간은 6~9시간(4주는 8~11시간, 13주와 14주 최종 프로젝트는 12~16시간)이고, 세션마다 무엇을 어디까지 하면 되는지는 문서 앞쪽의 "하루 1시간으로 나누면" 절(예: [1주 문서](fe-collab/week1/week01-http-devtools.md))에 표로 정리되어 있습니다.
- 첫 실행에는 Gradle 과 pnpm 이 라이브러리를 내려받으므로 인터넷 연결이 필요합니다. 1주차부터 `curl` 을, 응답 JSON 을 읽는 데 `jq` 를 씁니다. 둘 다 `curl --version`, `jq --version` 으로 설치를 확인하세요.

## 페이스 선택

한 세션은 하루 1시간(50~70분)이고, 전체는 118세션입니다. 주차별 세션 수는 1주 7, 2주 8, 3주 8, 4주 10, 5주 8, 6주 6, 7주 6, 8주 7, 9주 6, 10주 8, 11주 7, 12주 7, 13주 14, 14주 16 입니다. 걸리는 기간은 **주당 세션 수**로 정해집니다. 기간은 세션 합계를 주당 세션 수로 나눈 값을 올림한 주 수이고, 개월 수는 한 달을 4.35주로 보고 0.5개월 단위로 반올림한 값입니다.

| 코스 | 주당 세션 수 | 계산 | 기간 | 방식 | 추천 대상 |
|------|--------------|------|------|------|-----------|
| 느긋하게 | 주 3회 | 118 ÷ 3 = 39.3 → 40주, 40 ÷ 4.35 = 9.2 → 9개월 | 40주 (약 9개월) | 모든 세션을 그대로 진행 | 일과 병행하며 여유 있게 진행하는 경우 |
| 평일 매일 | 주 5회 (평일 매일) | 118 ÷ 5 = 23.6 → 24주, 24 ÷ 4.35 = 5.5 → 5.5개월 | 24주 (약 5.5개월) | 모든 세션을 그대로 진행 | 평일 하루 1시간을 꾸준히 확보할 수 있는 경우 |
| 매일 | 주 7회 (주말 포함 매일) | 118 ÷ 7 = 16.9 → 17주, 17 ÷ 4.35 = 3.9 → 4개월 | 17주 (약 4개월) | 모든 세션을 그대로 진행 | 짧은 기간에 몰아서 끝내려는 경우 |
| 압축 | 주 5회 (평일 매일) | (118 − 18) ÷ 5 = 20 → 20주, 20 ÷ 4.35 = 4.6 → 4.5개월 | 20주 (약 4.5개월) | 건너뛰는 세션 18개를 뺀 100세션을 진행 | 평일 하루 1시간으로 기간을 줄이고 싶은 경우 |

마일스톤은 세션 번호로 5주 끝이 41번째 세션(1~5주의 7 + 8 + 8 + 10 + 8), 8주 끝이 60번째 세션(41 + 6 + 6 + 7), 14주 끝이 118번째 세션입니다. 하루에 한 세션씩 하면 41일째, 60일째, 118일째입니다.

압축 코스는 문서를 줄이지 않고, 각 문서의 세션 표에서 `(압축 코스에서는 건너뜀)` 으로 표시한 세션을 빼는 방식입니다. 이렇게 표시한 세션은 모두 18개이고 세 종류입니다. 첫째, 1~13주 각 주의 연습문제·퀴즈 세션 13개입니다. 둘째, 문서에서 선택이라고 표시한 단계의 세션 3개(5주 4단계와 7절, 10주 4단계, 13주 3-D)입니다. 셋째, 개념 절을 훑기만 해도 되는 세션 2개(3주 9~11절, 4주 3절)입니다. 5주와 8주의 마일스톤 체크, "먼저 손으로" 의 필수 단계, 체크리스트와 학습 노트 세션, 14주 최종 프로젝트는 건너뛰지 않습니다. 5주와 8주 마일스톤 체크와 14주 최종 프로젝트가 "넘어가도 된다" 를 판단하는 지점입니다.

## 각 주차 문서 구성

1. 학습 목표와 예상 시간, 전제와 준비물
2. **🖐 먼저 손으로** — 결과를 예측하고 실행해 비교하기, 일부러 망가뜨려 보기, 빈칸 채우기
3. 개념 설명과 실제로 실행해 확인한 예시 (손 실습에서 막혔을 때 펼쳐 보는 부분)
4. "TypeScript 와 비교" 박스 (백엔드 용어를 TypeScript·프론트 용어에 대응시킴)
5. 연습문제, 퀴즈(정답은 접어 둠), 체크리스트

## 학습 방법

읽기만 하면 "알 것 같은 느낌" 만 남습니다. 각 주차는 **먼저 손으로 → 읽기 → 확인** 순서로 진행합니다.

1. **먼저 손으로.** 문서를 읽기 전에 "먼저 손으로" 절부터 합니다. 결과를 먼저 적고, 실행하고, 틀린 예측에 표시합니다. 틀린 예측이 가장 값진 학습입니다.
2. **읽기.** 막힌 부분을 개념 절에서 찾아 읽습니다. 설명 문서는 막혔을 때 펼쳐 보는 사전으로 씁니다.
3. **확인.** 연습문제·퀴즈·체크리스트로 내가 설명할 수 있는지 확인합니다. 설명이 안 되면 이해한 것이 아닙니다.

추가로 지킬 규칙은 세 가지입니다.

- **명령은 직접 실행해서 출력을 눈으로 확인합니다.** 문서에 적힌 출력과 다르면 그 차이가 학습 대상입니다.
- **15분 넘게 막히면** 에러 메시지의 첫 줄을 읽고, 그래도 안 되면 질문합니다.
- **매주 끝에 5분** 동안 학습 노트(`my-notes.md`)를 적습니다.

```markdown
## N주
- 예측이 틀렸던 것: (요청/예측/실제/왜)
- 오늘 처음 본 에러 메시지: (원문 + 원인)
- 가장 오래 막힌 부분: (무엇이 막혔고 어떻게 풀었나)
- 내 말로 한 문단 설명: (오늘 배운 개념을 TypeScript·프론트 용어와 비교해서)
```

| 시점 | 통과 기준 |
|------|-----------|
| 5주 끝 | 백엔드 PR 두 건을 읽고 요청 호환성, 응답 변화, 테이블 영향, 프론트에서 깨지는 곳, 작성자에게 물을 질문(각 3개 이상)을 서면으로 설명. 4주의 PR 읽기 절차를 순서대로 따름 |

## 빠른 시작

참조 API(8080)와 프론트(3000)를 함께 띄웁니다. 명령은 `labs/frontend/README.md` 와 같습니다.

```bash
# 터미널 A: 참조 API (8080)
cd labs/backend && ./gradlew :week25:bootRun

# 터미널 B: 프론트엔드 (3000)
cd labs/frontend
pnpm install
pnpm gen:api     # ../backend/week25/openapi.json -> src/api/schema.d.ts
pnpm dev         # http://localhost:3000
```

- 데모 로그인은 `demo` / `demo1234` 입니다. 읽기(책 목록·검색, 대출 목록)는 로그인 없이, 쓰기(책·회원 등록, 대출, 반납)는 로그인 후에 됩니다.
- 백엔드는 H2 메모리 DB 라서 껐다 켜면 데이터가 비어 있습니다. 대출 화면을 쓰려면 먼저 책과 회원을 등록하세요.
- 백엔드 없이 화면만 개발하려면 `NEXT_PUBLIC_API_MOCKING=enabled pnpm dev` 로 MSW 를 켭니다(9주).
- 테스트는 `pnpm test`(Vitest 30개, 백엔드 불필요)와 `pnpm e2e`(Playwright, 백엔드가 8080 에서 떠 있어야 함)입니다. 테스트의 층과 선택은 12주에서 다룹니다.
- 이후 문서의 명령은 별도 언급이 없으면 저장소 루트에서 실행하는 것을 기준으로 합니다.
